为什么需要它 · 设计初衷

作为『一切皆插件』架构的执行中枢，为所有工具插件提供统一的注册表与执行管线：工具插件在此注册 schema 与 executor，管线依次经过 pre-execute 策略门（allow/deny/ask）→ guard → execute 包装（超时/重试/指标）→ post-execute 改写 → 结果冻结，并支持并行/独占并发分类与协作式取消。RC7：Code Mode 更名 PTC mode、图片子结果经 exec.deferContext 注入、系统提示词文案更新。解决 Agent 框架最核心问题——工具如何被定义、向模型呈现、被策略拦截、被安全执行。

📜 core 产品组『产品 API 脊梁』之一（stable API），与 session/system-prompt/agent 并列；随仓库 2026-06 起步、2026-08-13 公开。迭代出 Code Mode（run_code 传输）、canonical tool output 契约、render-intent 卡片体系等。

① 实现逻辑

工具注册表与执行管线(ctx.tools)。ToolRuntime 服务(static inject ['systemPrompt']) 管理分层工具注册(ScopedLayers)与可见性解析器(view)，按 mode(native/code/both) 决定模型可见工具集；execute() 走 pre-execute → execute → post-execute 三个瀑布(pre 允许/拒绝/询问、execute 包装超时/重试、post 接受/替换/阻断)，最后发 tools/result 观察事件；approval 请求经 ctx.get('approval') 可选 seam 路由，codeRuntime 经 ctx.get('codeRuntime') 可选。RC7：Code Mode 的成功的含图片子结果经 exec.deferContext 以来源归属上下文注入(不再直接拼进外层结果，code-mode.ts:565-571)；UI 呈现名更名 PTC mode(Plan-Think-Code)；system prompt 文案更新(CODE_ONLY_INSTRUCTION 等)。
