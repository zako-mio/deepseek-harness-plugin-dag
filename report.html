五、反思/分析/建议

1. 增量级联的成立条件是「先测后定」，不能凭上轮经验外推

上一轮 210/210 全变，若照搬结论直接全量重建，会白白重做 122 个「仅版本号变化」包。差异分析必须先于策略决策——这是本轮省下约 38% 分析量的根本原因。

2. 差异对齐的键必须与分析单元的键一致

DAG 的节点键是包 id，不是目录路径。本轮 10 处域搬迁若按路径比对，会产生「删除 + 新增」的假象并触发无谓重做。对齐键选错，增量分析直接失效。

3. 门控里的「黄金值」是负债，不是资产

本轮 4 类故障中有 2 类源自旧脚本/旧测试钉死派生统计量（50 组、264 边、19 disabled、G20 双向）。这类断言在版本升级时必然失效，且失效方式具有欺骗性——报错指向「断言失败」，但真实原因是「数据变了而期望没变」。

建议：门控断言应写不变量（集合相等、划分完备、端点合法）而非快照值。本轮已将三处分类学表全部改为数据派生，并把 headless 的 hover 断言改为「从 DATA.groupEdges 独立复算后比对」——后者比原黄金值更强，且不随拓扑漂移。

4. 「子 Agent 声称成功」不等于「产物已落盘」

13 个 agent 全部返回 success，但中途列目录时曾观察到某分片文件尚未出现（实为写入时序，非失败）。验证必须以磁盘产物为准，这也是 v021-validate.py 断言「复用片 ∪ 委派分片 == 节点全集」的价值所在。

5. 环境限制应转成可复现的代码，而非一次性绕过

maxDepth: 0 阻断委派 → 转 workflow；snap chromium 不可用 → 浏览器路径自动探测并写进脚本注释。后者让 headless-verify-l3.py 在两种环境下都能跑，而不是留一个「本机特殊处理」。
